# Новое оружие ближнего боя — правила и порядок работы

Пользователь жалуется на одно и то же: «в быстром бою оружия похожи», «модель не похожа на предмет», «герой сплющивается / лежит».
Поэтому каждое новое оружие обязано пройти **весь** список ниже. Отвечать пользователю и писать комментарии — по-русски.

## 1. Где что лежит (одно оружие — один модуль)
Новое оружие — отдельный модуль `src/js/12k_<буква>_<имя>.js` (после 12k_g, до 13), всё в блоке `{}`:
1. **Запись в `WEAPONS`** присваиванием + `id` и `_defs = {}` (как в 12k_e_melee2): `slot: "melee"`, `name` — «прилагательное + предмет»
   по сути вещи («Боевой топор», «Громовые нунчаки»), `info`, `stats: [дальность, скорость, урон]` 1..5, `rangeK`, `mod`
   (`reach/st/rc/ac/dmg/knock/stun/lunge/fxR/fxW`). id не должен совпадать с оружием врагов в `_weapon` (`claw`, `knives`, `hammer`…).
2. **Модель `WEAPON_DRAW[id] = { off, draw(ctx, ch, p, accent, hq) }`** — см. §2.
3. **Набор `registerKit(id, { moves, choose, pose, takedown })`** (12d_kits): `pose` — позы ВСЕХ атак, `moves` — свои приёмы,
   `choose` — подмена ТОЛЬКО `rise`/`dash`/`flurry` (обычные `slash1/2/3` не трогать — после `kitChoose` их подменяет рукопашка 12f_martial).
4. **Добивание** `registerTakedown(id_td, {...})` вместо `xcut` (громила и воздух — встроенные).
5. **Трюки** `registerTricks(id, [3 трюка])` (12e_tricks) — игра с оружием в покое, на ходу и в прыжке.
6. **Фирменные эффекты** `registerWeaponFx(id, { slash, thrust, hit, hitRate })` (12d_kits).
7. Вторая рука с оружием — `backHand(p, off)` (12k_e) / как второй автомат в 12k_d. Превью карточки — хук `WEAPON_DRAW[id].preview(P, ch, act)`.

## 2. Модель оружия должна узнаваться с первого взгляда
- Силуэт **по реальному предмету**: у топора лезвие с ОДНОЙ стороны древка (выпуклая кромка, «борода» к рукояти, обух сзади) —
  симметричный полумесяц с двух сторон читается как молот/кольцо; у копья — длинное древко и листовидный наконечник; у катаны —
  изогнутый клинок, цуба и оплётка; у глефы — рукоять посередине и клинки на обоих концах.
- Начало координат — кисть, ось X — вдоль предплечья, `off` — наклон в покое. Масштаб: персонаж ≈ 40 ед., голова ≈ 15 ед.
  Оружие 10–35 ед.; детали меньше 0,8 ед. не видны.
- Стиль: тёмная заливка (`#14151b…#23252e`), **неон `accent` только по рабочей кромке** (`wGlow` в hq), белый блик 0,15–0,25.
  Металл — на 1–2 тона светлее древка, чтобы части различались.
- Без аллокаций в кадре: константы-массивы вне `draw`, никаких `new`/литералов-объектов в цикле отрисовки.
- Проверка глазами: `node tools/weapons-sheet.js` (карточки «Арсенала» — покой, удар, в бою) и крупно `kit-*-sheet.js <id> файл 4`.

## 3. Уникальность в быстром бою — обязательный минимум
У каждого оружия должно отличаться от всех остальных **не меньше четырёх** из шести пунктов (в быстром бою первыми видны 1–3):
1. **След удара** (`slash/thrust` в `registerWeaponFx`) — своя форма, а не общая дуга: прямая линия (копьё), два полумесяца (глефа),
   тонкий проявляющийся разрез (катана), тройная широкая дуга + трещины (топор), борозды (когти), молнии (нунчаки), сектор ветра (веер).
2. **Попадание** (`hit`) и **звук** (`hitRate`: тяжёлое 0,7–0,9, лёгкое 1,15–1,3) — своё.
3. **Силуэт позы удара** (`kit.pose`): стойка (низкая/широкая/высокая), хват (одна/две руки, обратный), работа корпусом (присед, выпад,
   оборот `turn`), откуда идёт замах. Сравнить кадры с соседним оружием той же группы — силуэты не должны совпадать.
4. **Ритм** анимации: подготовка/доводка (без смены урона и хитбоксов) — тяжёлое с замахом и долгой доводкой, лёгкое — короткие уколы.
5. **Свои комбинации** (минимум 2, условия в ритме: сильная доля, «и», perfect, грув, дистанция, враги с двух сторон).
6. **Трюки** — 3, по характеру оружия (вертушка, перехват, на плечо…).

## 4. Чего нельзя (уже ломали)
- **Не сплющивать**: повороты корпуса только параметром позы `turn` (обороты), не `sx`; `sx/sy` в пределах 0,8–1,2.
  Тяжёлым позам ограничивать наклон (`capLean`, |lean| ≤ 0,3) — иначе герой «лежит».
- Не подменять в `choose` обычные удары серии — иначе пропадает рукопашный бой (12f_martial, доля ≥ 20%, `tools/martial-share.js`).
- Угол оружия в трюках/позах после оборотов — через `wrapPi`/`trickEnd`, иначе клинок «откручивается» назад.
- Подвижные части (цепь, вторая палка, веер в полёте) — физика/позиция на герое и в тех же координатах, что хитбокс.
- Урон за нажатие ≈ кинжалу ±10–15% (`weapons-test` печатает долю), сильные стороны уравновешены слабыми.
- В low (`g.fx.low`) — облегчённые эффекты; без длинных кадров (`perf-test`).

## 5. Проверка перед коммитом
`node tools/build.js`, затем (`PW=$(npm root -g)/playwright node tools/<файл>.js`):
`kit-<группа>-test` (свои комбинации вызываются и попадают, добивание завершается), `weapons-test`, `tricks-test <id>`,
`squash-test 3`, `martial-share 30 <id>`, `combos-test`, `smoke-test`, `screens-test`, `weapons-screen-shot.js` (карточки на 800×380 и 1100×560),
`PROFILES=pro MELEE=<id> balance-test.js 150 normal` (сравнить с dagger).
Глазами: лист поз, лист трюков (`tricks-sheet.js <id>`), раскадровка боя `anim-strip.js <файл> <id> 36 60` **рядом с раскадровкой
соседнего оружия** — если по кадру нельзя сказать, какое это оружие, уникальность не достигнута.
Затем — строка в таблицу архитектуры CLAUDE.md, строка в README, счётчики «Арсенала» в CLAUDE.md. Реальные устройства не проверялись — так и писать.
