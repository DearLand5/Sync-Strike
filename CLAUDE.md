# CLAUDE.md — Sync Strike

Мобильная 2D-игра в браузере: ритм-файтинг, бой синхронизирован с MP3, который загружает игрок.
Пользователь общается на русском — отвечать и писать комментарии в коде на русском.

## Режиссёр
**«Режиссёр»** — так называем систему «части трека → эффекты арены» (одно слово, по просьбе пользователя): анализ частей (`sectionBars/buildSections/finishSections` в 04_analyzer) → события и состояние часов (`kind`, `section`, `sectionT`, `dropIn`… в 05_clock) → варианты эффектов арены (`updateVariants`, `variantBack/Front` в 09_arena). Жалоба «Режиссёр не работает» = в треке с явной структурой арена не реагирует на брейк/дроп/нарастание. Проверка — на настоящей музыке: `tools/real-sections.js` (ниже), а не только на синтетике.
**Ручная настройка** (по просьбе пользователя; отдельный экран `scr-director` «Режиссёр» — пункт главного меню и кнопка на экране «Музыка»; свой мини-плеер ▶/время, «Назад» → откуда пришли (`dirReturn`), «Музыка», «В бой»; модуль `04c_director.js`): режимы **Авто** (части из анализа + «Смены частей» −2..+2 = множитель цены границы `DIR_SENS` 2,4/1,6/1/0,62/0,38 → `segmentBars` по сохранённым признакам тактов `map.bars`, без нового анализа), **Вручную** (список частей `[{s, k}]` в ИСХОДНОМ времени трека; инструменты — см. «Редактор» ниже), **Выкл** (одна часть groove, `map.directorOff` → арена без эффектов по частям и без «trend»-свечения). Хранение — `Store "dir.<ключ трека>"` (`Director.load/save`; ручная разметка сохраняется и в режимах Авто/Выкл). Применение: `Director.apply(base.map, dir)` ДО `Tempo.makeMap` (в `prepareTrack`, `applyTempo`, `Game.applyDirector`); `track.director`; в бою заблокировано, как темп. Части в ручном режиме дополняются энергией/уровнем/басом/верхами по огибающим карты (`Director.fill`; дроп/кульминация → level intense). Редактор (третья версия, по просьбе «проще, точнее, удобно и на телефоне»): **контекстные панели** — трек играет → только «Нажмите, когда начинается часть» (8 крупных кнопок «+ …», сетка 4×2 / 2×4 на узком; часть начинается «сейчас» −0,12 с, магнит к ближайшей линии сетки; `Director.mark/tidy`), пауза → только «Часть N из M» (◀ ▶, «▶ Отсюда», характер, **точное начало/конец** — поля `мин:сек.мс` во времени трека с темпом + кнопки ◂ ▸ с удержанием: 10 мс, повтор через 0,4 с, шаг ×1,3 до 0,25 с, серия — одна запись истории; «✂ Разрезать здесь», «Убрать часть»); при паузе выбирается часть под курсором. **Карта масштабируется**: два пальца (щипок), колесо мыши, кнопки −/+, клавиши +/−; при увеличении палец по пустому месту двигает карту, вид едет за курсором трека; обзорная полоска `#dir-ov` всего трека с рамкой видимой области (нажать/тянуть). **Границы без шага**: ручка (белая линия + круг снизу, захват пальцем ±22 px, мышью ±12 px), время во всплывашке при перетаскивании; **магнит** («Дополнительно» → Выкл/Доля/Такт/4 такта, `settings.dirSnap`) притягивает только если линия сетки ближе 10 px; сетка тактов/долей видна на карте при увеличении; минимальная часть `DIR_MIN_LEN` 0,5 с. «Дополнительно» (свернуто): магнит, «Разметка из анализа», «Начать с нуля», список клавиш. Шапка: Авто/Вручную/Выкл, ↶ ↷ (80 шагов, Ctrl+Z/Y), 👁 предпросмотр (`#dir-pv`). Клавиши: пробел, 1–8 (играет — отметка, пауза — характер выбранной), ←/→, Alt+←/→ ±10 мс (Shift — 100 мс), Delete. Указатели — Pointer Events с `offsetX` (верно и в повёрнутом `#app.rot`, щипок проверен через CDP touch). Тест — `tools/director-ui-test.js`.

## Главное правило сборки
- Исходники — `src/index.template.html` (HTML + CSS + DOM экранов) и модули `src/js/NN_*.js`.
- **`index.html` — сгенерированный файл, руками не править.** После любых правок: `node tools/build.js`
  (склеивает модули по номеру в один IIFE и подставляет вместо `/*__JS__*/`). `index.html` коммитится.
- Порядок модулей важен (номер в имени файла). Всё в одной области видимости IIFE; для тестов наружу
  выставлены `window.__game`, `window.THEMES_IDS`, `window.DIFFS_REF`, `window.ATTACKS_REF`.
- Без внешних библиотек и сервера. Единственное внешнее — Google Fonts (с запасными шрифтами).

## Тесты (Node + Playwright, браузер уже установлен)
Запуск: `PW=$(npm root -g)/playwright node tools/<file>.js [args]`
- `test-analyzer.js [44100|48000]` — точность анализатора на синтезированном демо-треке (эталон: 116 BPM,
  ошибка долей ≤ 6 мс, сильная доля на 1-й доле такта, части демо: intro 0 → build 8,5 → drop 25,1 → break 58,2 → climax 74,7 → outro 107,8 (финал демо, 4 такта); хвост тишины в 2 с отдельной частью не выделяется). Без браузера.
- `stress-analyzer.js [44100|48000] [фильтр]` — «трудные» синтезированные треки с известными долями (4/4 128, медленный 72,
  DnB 174 ×2 рисунка, синкопы+свинг, 18 с пэдов до бита, дрейф 118→124 с дрожанием, смена темпа 100→140, брейк 8 тактов, сильное
  сжатие+шум). Печатает: найденный BPM, октавное соответствие (`*` — вариант ×2/÷2 внутри 80–160 BPM допустим, `!` — вне),
  долю долей с ошибкой ≤ 30/60 мс, медиану, точность в брейке, попадание сильной доли на 1-ю долю такта, отношение числа долей.
  `ANALYZER=<путь>` подменяет 04_analyzer.js (сравнение «до/после»). Итог: все треки ≥ 98% долей ≤ 60 мс, кроме «DnB бочка на «и»»
  (известный предел: бочка только на «и» — на 44100 сетка 87 BPM встаёт на полдоли в сторону, на 48000 находится 116 BPM). Без браузера.
- `smoke-test.js`, `screens-test.js` — экраны, все арены, пауза, повтор, режимы, победа/поражение.
- `skins-sheet.js [файл] [масштаб] [id,id] [колонок]` — контактный лист скинов (стойка и бег с замахом) в `.shots/skins-all.png`; `skins-screen-shot.js` — экран «Облик» (800×380, 1100×560, категории, выбор кликом) и кадры боя с несколькими скинами. Перед правкой отрисовки персонажа — смотреть листом глазами.
- `features-test.js` — добивания (4 вида), уклоны (3 вида), части трека, поворот экрана в портрете.
- `bot-test.js [сек]` — бот играет волны; `balance-test.js [сек] [easy,normal,hard]` — 3 профиля × сложности.
- `perf-test.js [сек]` — длинные кадры, пересборки тайлов фона (должно быть 0 в бою), память. `SKIN=oni` — прогон с другим скином. `THEME=<id>` — принудительная арена (в первом 10-секундном окне ~24 «пересборки» — загрузка, это норма и для старых арен).
- `gpu-test.js` — имитация сброса GPU: фон (внеэкранные тайлы) должен перерисоваться во всех трёх вариантах. Перебирает все арены из `THEMES_IDS` (`THEMES=id1,id2` — выборочно).
- `sfx-test.js` — все записанные звуки декодируются, все методы SFX работают в режимах samples/synth, голоса не текут.
- `library-test.js` — библиотека треков (IndexedDB): добавление, повтор без анализа, выбор, восстановление после
  перезапуска, автоудаление по лимиту, ручное удаление, автосохранение волн/позиции трека и «Продолжить», страницы/поиск/сортировка (800×380).
- `sync-test.js [сек]` — автоподстройка задержки (`AutoSync`): игрок +60 / −50 мс и с разбросом ±40 без смещения, автоподстройка выкл, +300 (вне окна). Идёт ~6 мин (5 сценариев по 60 с реального времени).
- `beat-attack-test.js [сек на темп] [сложность]` — удары врагов на долю: расстояние до ближайшей доли (медиана < 10 мс, p95 < 25 мс), число долей замаха по типам на 116/70/160/200 BPM (темп подменой карты в clock).
- `timefx-test.js [сек] [сложность]` — эффекты времени в плотном бою (6 врагов): доля замедления, входы/мин, стоп-кадры.
- `sections-test.js [44100|48000] [фильтр]` — Режиссёр на синтетике (Node, без браузера; код возврата 1, если kind < 98% или есть лишние/пропущенные границы; `BARS=1` — признаки тактов, `DRIVE=1` — интенсивность частей): синтезированные треки с известной разметкой (EDM intro→build→drop→break→build→drop→outro 128 BPM, то же 140 BPM с 4-тактовыми частями, вариации внутри дропа, «живой» EDM с разбросом ударов ±30% и тактов ±3 дБ, ровные грувы с филлами/сменой рисунка без структуры, плавная динамика, сжатый трек). Печатает: границы найдено/истина, лишние/пропущенные, ошибка границы (мс, доли), доля границ на сильной доле и на 4-тактовой фразе, точность kind по времени, момент события дропа в `RhythmClock`, задержку включения дропа в `ArenaRenderer.updateVariants` и остаток нарастания после дропа. `ANALYZER=`, `CLOCK=`, `ARENA=` подменяют 04/05/09 (до/после). Итог (после перехода на реальную музыку): kind 99,8%, 0 лишних/пропущенных, ошибка границы ≤ 5 мс на 44100 и 48000 (схема до «Режиссёра»: 52%, 30 лишних, ошибка до 3,7 с).
- `real-sections.js [опции] <папка|файлы>` — **Режиссёр на НАСТОЯЩИХ треках** (Node; PNG-карты — через Playwright). Декодирует ffmpeg (`/usr/bin/ffmpeg`), гоняет настоящий анализатор, часы и `updateVariants`; печатает по треку BPM, части (kind/уровень/интенсивность), доли времени по kind, «молчит» (нет ни одной части build/drop/climax/break) / «мало» (эффекты арены < 15% боя), и по разметке `tools/real-sections.json` (ручная «истина» только по временам, без аудио): точность kind по времени, лишние/пропущенные границы (окно 4 с; `soft` — спорные части не считаются), найденные дропы/брейки/нарастания, **охват и точность эффектов арены** против разметки, «дёрганье» на ровных треках. ## Принятые решения (по просьбам пользователя)
- Стиль: **Shadow Strike + неон** — чёрные силуэты, неоновый контровой свет, ореол; персонажи маленькие (как Hollow Knight).
- **28 скинов игрока** (6 классических + 22 новых в `07b_skins.js`) в категориях Классика / Кино / Игры / Фэнтези / Sci-Fi / Хоррор; у скина поля `cat` (категория) и `from` (подпись-вдохновение на карточке). Образы оригинальные (архетипы жанров, без чужих персонажей и логотипов). «Тень» (`shade`) не менять — по ней делается иконка APK. Экран «Облик» (13_ui `buildSkins/_skinCat/_skinMark`): вкладки-категории со счётчиками, при входе открывается категория выбранного скина, карточки и превью строятся и рисуются один раз (превью — `<img>` из `toDataURL`, не canvas: canvas стирался при сбросе GPU и иконки пропадали) (дальше только фильтр `hidden` и `aria-pressed`); на низком экране (≤520 px) карточки компактные. Сохранённый `settings.skin` работает как раньше (неизвестный id → `shade`). `noEyes: true` — без глаз (скин «Светоч» `lamp`, фэнтези: голова — белый свет `HEAD_PARTS.lumen`, ореол и комок света у груди `MARK_PARTS.orb` — кэшированный на контекст радиальный градиент (`lumenGrad/lumenGlow`, WeakMap; концентрические круги давали ступеньки)); `mono: true` у скина — рисуется один глаз (повязка, линза, дыра в мешке). Новый скин: запись в `SKINS` + при необходимости детали в `HEAD_PARTS/BACK_PARTS/MARK_PARTS/HEM_PARTS`; смотреть `tools/skins-sheet.js`.
- Враги — случайные варианты снаряжения и знаки на одежде.
- **15 арен** (6 базовых в 09_arena + по 4 в 09b/09c + «Морок» в 09d); подбираются под трек по признакам сигнала (не по жанру); выбор вручную сохраняется на трек.
  Профили новых арен настроены по синтетическим признакам (реальных MP3 не было) — если на треках пользователя какая-то арена
  выпадает слишком часто/редко, подкручивать её профиль в `rankThemes`, проверяя, что базовые не теряют свои треки.
- Фон реагирует на части трека (Режиссёр): нарастание (полоса света снизу вверх, штрихи, импульсы краёв, «вдох» перед дропом), дроп/кульминация
  (лучи прожекторов, взрыв лучей и ударная волна на входе, мягкий строб половинами, смена неоновых цветов; кульминация — веер лучей и «занавес»),
  брейк (конус прожектора, пыль в луче, обесцвечивание), спокойные части (приглушение, светлячки), бас/верха. Подробности — строка 09_arena.
- **«Удар в бит»** (по просьбе «как в Dead as Disco: импакт, бьёшь/стреляешь/двигаешься под бит»; 12_combat `execute/updateBuffer`, 14_game `sfxAt`):
  при `assist` момент удара подгоняется к доле в ОБЕ стороны — раннее нажатие (до `min(0.2, 0.4·P)`) растягивает подготовку, нажатие perfect/good
  на долю или после неё сокращает подготовку до `BEAT_MIN_STARTUP` 0,025 с (у рывка ещё и путь — до 0,045 с). Раньше удар шёл на 50–80 мс ПОЗЖЕ доли
  (подготовка 0,05–0,08 с + путь рывка до 0,17 с после нажатия на долю). `act.impactSong` — расчётный момент удара, `act.onBeat` — удар точнее 35 мс от доли.

  `Game.sfxAt` → `AudioManager.ctxTimeAt`: звук смешивается с той же позицией трека, поэтому совпадает с долей при любой задержке вывода
  (Android — десятки мс); в замедлении и если момент уже в аудиоконвейере — сразу. Удар в долю: бочка `beatHit`, белая вспышка в точке удара,
  отсвет экрана в цвет героя (`impactFlash`, HUD), сильнее толчок камеры; выстрел в долю — белая вспышка у ствола. Шаги бега — целое число шагов
  на долю (или шаг на две доли), фаза подтягивается к доле (`Player._stepRate`). Камера «качает» на каждой доле (сильнее на сильной, по

  на новом уровне — подпись и звук. На урон/баланс грув не влияет (только очки через `chain`). Проверка — `tools/beat-feel-test.js`.

  `track = { buffer, map, meta, base: { buffer, map }, tempo }`: **`buffer/map` — то, что играет и видят часы/бой; `base` — исходный звук и анализ.**

  Правка долей (поверх анализа, меняет карту, не звук): `tempo.fix = { k, half, shift }` — `k` ±: ×2 / ÷2 (сильные доли пересчитываются по
  совпадению с исходными), `half` — сдвиг на ½ доли, `shift` — мс (±10 за нажатие, в уже изменённом темпе), «Сбросить».
  `tempo = { rate, keep, fix }`. Хранение: библиотека — `meta.tempo` (`TrackLibrary.setTempo`; `add` переносит его при повторном открытии файла),
  демо — `Store "tempo.demo"`; исходная карта анализа в `data` не перезаписывается. Автосохранение несёт `tempo` (songPos — во времени растянутого
  трека); `continueBattle` перед стартом применяет темп из автосохранения. Арена подбирается по **исходным** признакам (`track.base.map.features`) —
  смена темпа арену не меняет. **Рекорды раздельные**: при темпе/правке ≠ оригинал ключ `best.<key>@<pct>[x<k>][h].<mode>` (`Tempo.tag`),
  оригинал — прежний ключ; в итогах подпись «темп 125%». Во время боя (и паузы) карточка темпа заблокирована.
- **Автоподстройка задержки** (`AutoSync` в 05_clock, `Game.sync`, настройка `autoSync`, по умолчанию вкл): `CombatSystem.execute` отдаёт
  `judge()` нажатия атаки в `sync.add(j)` — это исходный delta (assist сдвигает только удар, не отметку нажатия). Учитываются только
  |delta| < окна good; выборка 24 нажатия, усечённое среднее 25–75% и IQR; шаг = 0,6·ошибка, ≤ 8 мс, не чаще раза в 2,5 с, мёртвая зона
  max(12 мс, 3 стандартные ошибки), IQR > 70 мс — не трогаем, итого ±120 мс за бой от значения на старте. **Знак:** delta > 0 = «позже»,
  `songTime = звук − latencyMs`, поэтому `latencyMs += ошибка`. Запись тихая (`settings.v` + `save`, без `clock.reset`, который делает `settings.set`);
  старые delta в выборке сдвигаются на шаг. Тост «Синхронизация подстроена: ±N мс» не чаще раза в 20 с. Работает только в `state === "battle"`
  (практика тоже). HUD: шкала «рано ↔ поздно» под индикатором доли (`HUD._beatGuide`, отметки `sync.marks`, 8 штук, гаснут за 6 с).
  Итоги: «Средняя ошибка» (медиана `sync.all`) и подсказка `#res-hint`, если автоподстройка выкл и |ошибка| > 25 мс. Уклоны в статистику не входят.

- **Декор арен — только на опорах.** Всё, что висит или стоит (гирлянды, фонари, вывески, провода, цепи, лампы, кроны),
  крепится к мачте/столбу/стене/кровле/балке/колонне, а опора рисуется **в том же слое параллакса**. Статика — в `paint`
  слоя (один раз в тайл), анимированная часть — в `dyn` того же слоя (рисуется сразу после его тайла с тем же сдвигом `off`),
  связь — якоря `A` (координаты тайла, пишет `paint`). Нельзя рисовать подвесы в `mid`/`back` по случайным координатам:
  слои едут с разной скоростью и закрывают друг друга. Провисание — `wire`/`wirePt` между реальными точками опоры.
  Ряды зданий — `layoutRow` (ровно на ширину тайла, без обрезки краем и шва). Парящее допустимо только там, где это
  часть стиля (кристаллы в «Бездне», платформы-излучатели). Низкие слои задают `top` (доля высоты) — хранится только
  нижняя часть тайла; дальние слои (`haze` ≥ 0.4) рисуются в dpr 1. У тайла справа запас `TILE_PAD` против просвета шва.
  Отражения в полу (`refl`) — только при `R.amount >= 1` (не на low). Платформы: опоры до пола, в «Бездне» — излучатели.

- **Атаки врагов по долям с отсчётом** (11_enemies `_requestAttack/_windup`, отрисовка `CombatSystem._drawWindTicks`): замах = N долей
  (`ENEMY_TYPES.beats`: blade/swift 1, gunner/brute 2; `DIFFS.windBeats` — добавка; темп > 150 BPM +1, > 190 ещё +1, < 85 −1; потолок ~1.45 с;
  минимум времени реакции = `wind*diff.wind*0.6`). `strikeAt` — музыкальное время доли (через `clock.nextBeatAfter`), удар срабатывает по `songNow`
  (с упреждением полкадра), а не по накоплению dt. Под замедлением враг не успевает замахнуться (`windT < 0.85*windDur`) — удар переносится на
  следующую долю, «между» долями не бывает. Над головой 1–2 засечки (зажигаются на долях, последняя — удар, белая) + кольцо-вспышка (не в low),
  глаза вспыхивают на каждом тике (`eyeBoost`). Урон ближнего боя начинается через `MELEE_HIT_DELAY` 0.04 с после старта удара — окно идеального
  уклона (`perfectDodge`, уклон нажат за ≤ окна до удара) получается почти центрированным на доле. Лог ударов для тестов — `game.strikeLog` (если задан).

## Баланс

Пользователь жаловался и на «слишком тяжело», и на «слишком легко» на Норме; последняя жалоба — «волны слишком простые и
короткие» (профи проходил 6 волн за 74 с), поэтому волны стали втрое длиннее по натискам. Ориентир (balance-test):
Норма — профи ≈ 25–30 с на волну (≈ 2,5 мин на 6 волн, остаётся ~70/130 HP), средний доживает до 6-й с небольшим запасом HP,

Замер 300 с (профили идут по одному, `PROFILES=pro` ограничивает список; в `balance-test` бот сбрасывает метку атаки при
зацикливании трека на ~175 с — раньше после петли бот переставал бить и «умирал» на 5-й волне):
Норма — pro 6 волн, 146 с, 72/130 (waveT 1,17,39,60,86,113), mid 6 волн, 177 с, 41/130 (1,18,40,72,102,140),

(1,23,48,78,107,139), mid на 3-й, casual на 1-й; Лёгко — pro 6 волн 117 с 151/169, mid 140 с 141/169, casual 187 с 82/169.
Последний замер (200 с, после атак врагов по долям): Норма — pro 6 волн 150 с 92/130, mid 6 волн 176 с 34/130, casual проигрыш на 4-й;
Тяжело — pro гибнет на 5-й, mid на 4-й, casual на 1-й (в пределах шума ±1–2 волны).

## Грабли (уже наступали)
- Тайлы фона кэшируются по положению пола **в покое** (`v.restFloorY`), не по текущему `floorY` — иначе
  сотни пересборок за бой и фризы.
- **Сброс GPU на Android** (нагрев, нехватка видеопамяти; чаще при 120 FPS) стирает внеэкранные холсты.
  Фон рисуется в тайлы один раз → после сброса пропадали здания/горы («фон упростился») + чёрная секунда.
  Защита: события `contextlost/contextrestored` на основном холсте и тайлах, проверка `isContextLost()`
  раз в 0.5 с (`ArenaRenderer.checkLost`), `invalidate()` пересобирает тайлы; во время сброса `render` пропускается.
  Любой новый внеэкранный холст, нарисованный один раз, обязан так же восстанавливаться. Старые тайлы
  освобождать сразу (`releaseTiles`, width = 0). В FPS-оверлее — счётчик «сбросы GPU».
- Ограничение кадров `fpsCap` (0/90/60) — накопитель времени в `loop`, не простой пропуск (иначе 90 на 120 Гц = 60).
- Импульсы часов после перемотки/повтора: `lastStrong` сбрасывать в `reset()`, иначе `exp(+большое)`.
- `mixHex` клампит t и каналы; `.card{display:flex}` перебивает `hidden` → глобальное `[hidden]{display:none!important}`.
- Состояние `results` нельзя перетирать в `onScreen()`.
- `decodeAudioData` отсоединяет (detach) ArrayBuffer — в библиотеку сохранять копию (`ab.slice(0)` на декодирование).
- **Режиссёр (части трека)**: прежняя схема (пики «новизны» по энергии без привязки к тактам) ошибалась на 2–4 с и давала 5–10 лишних частей; её заменило разбиение по тактам. Потом выяснилось, что синтетика (`sections-test`) этого не ловит: на реальных MP3 Режиссёр «молчал» весь бой. Причины (найдены `real-sections.js`, примеры):
  1) `energy` — среднее дБ за кадр, нормированное по перцентилям 8–97% дБ: у трека с сайдчейном/сильным сжатием лежит в 0,1–0,4 и «качает» с периодом такта, поэтому `e < 0.38 → calm`, размах < 0.2 → весь трек groove/calm (Raving Energy: calm 100%). Для частей теперь свои уровни в дБ по мощности такта.
  2) Последняя часть получала `outro` из-за спада `slope` на хвосте (затухание в конце файла) — 3,5 минуты после брейка = outro, эффекты молчат (EDM Detection Mode: outro 63% трека, Go Cart 34%, The Lift 32%).
  3) `intro` без ограничения длины (Breakdown: intro 97% трека — арена всё время приглушена).
  4) Цена границы λ=0,8 при абсолютных (не шумовых) единицах: на реальном треке ни одной границы → один groove (Cut and Run: 0 из 4 дропов, 0 из 2 брейков). Теперь λ в единицах σ² шума самого трека; σ считать по СЫРЫМ признакам, а не по отфильтрованным (медианный фильтр занижал шум в 3 раза и дробил ровный трек).
  5) Абсолютные пороги ступеней: у громкого трека весь дроп — это +1…3 дБ по общей громкости, а меняются верха/плотность событий; «горячая» часть — только относительно `Ihi` трека, ступенчатый подъём (интро → слои → тело, 40+ с) считается по окну 45 с, плавная волна громкости (синтетика «плавная динамика», эмбиент-«свелл») входом НЕ считается — для этого `edge` (резкость границы).
  Хвост тишины после звука (в демо 2 с) нельзя включать в признаки последнего такта. Параметры (λ 40, пороги 0,1/0,15/0,22, веса `I`) подобраны по 45 реальным трекам и проверены на 17 контрольных; при жалобах на «лишние смены частей» поднимать `SECTION_LAMBDA` (55: 33 лишних вместо 46, но на контроле теряются брейки), на «пропущенные дропы» — `isHot`-запас 0,22 и `edge` 0,1. Любую правку проверять: `sections-test` (44100 и 48000) + `real-sections.js` на реальных треках до/после, затем `director-test`.
  Ограничения: разметка делалась по картам глазами, слухом не проверялась (±3 с); для треков с неуверенным ритмом (conf < 0,5) частей мало по замыслу; песни с плавным нарастанием куплет → припев без резкой границы дропа не получают (только при заметном перепаде).
- Меняя формат/логику анализатора (или что хранится в карте), увеличить `ANALYSIS_VERSION` (03b_library) — сохранённые карты пересчитаются (сейчас 5: в карте `bars` — признаки тактов для «Смен частей» Режиссёра).
- Анализатор: энергия секций нормируется по диапазону громкости — у сжатого трека без динамики шум раздувался до «секций» и голосовал за
  фазу такта; теперь диапазон не уже 6 дБ. Октава темпа: без члена 4L (такт) выигрывали «2/3-темпы» (DnB 174 → 116); БПМ вне 80–160
  допускаются только как ×2/÷2 (медленные 72 → 144, DnB 174 → 87 — это нормально). Новые проверки анализатора гонять `stress-analyzer.js`
  на 44100 и 48000, а не только демо-трек.
- IndexedDB может быть недоступна (приватный режим, встроенный просмотр Artifact, WebView на `file://` — не проверено):
  `library.ok = false`, игра работает без библиотеки, экран библиотеки пишет «недоступна». Не делать её обязательной.
- Главное меню на низком горизонтальном экране (телефон ~380 px) не помещалось → `@media (max-height:520px)`
  делает `.menu-list` в две колонки. Добавляя пункты меню, проверять скриншотом 800×380.
- **Темп трека**: `setTrack(buffer, map, meta, base)` получает уже растянутые buffer/map — в библиотеку (`library.add/updateMap`) и в `Tempo.makeMap`
  всегда передавать **исходные** (`base`). WSOLA: окно 46 мс, поиск ±6 мс (при ±10 мс сдвиг ударов от исходных вырастал ~на 2 мс), одно положение
  окон на все каналы; начало трека без подъёма окна. Замер Chromium (контейнер): 3 мин стерео 44,1 кГц ×1,25 — ≈1,3 с, ×0,8 — ≈1,6 с, передискретизация ≈1,2 с;
  доли карты против ударов демо-трека на 125%: медиана |ошибки| ≈ 10 мс (исходник ≈ 3 мс), p90 ≈ 70 мс (транзиенты WSOLA). Растянутый буфер хранится
  только в памяти: после перезапуска пересчитывается из оригинала. `applyTempo` при `loading` откладывает последнее значение (`_tempoPending`).
  Правка `fix` без смены rate/keep не пересчитывает звук. Часы (`clock.setMap`) сбрасывают `correction` при смене темпа.
- Враги: без суперброни идеальный спам ударов держит их в бесконечном оглушении (урон по игроку = 0).
- Токены `AttackDirector` чистятся от исчезнувших врагов в `request()`.
- После добивания игроку возвращать `idle` только если он всё ещё в `takedown` (может быть `victory`).
- **Эффекты времени — только через регулятор** в `Game` (14_game.js): `slowmo(dur, scale, priority)` с приоритетами
  flair < dodge < takedown < finale и `hitstop(t)`. Прямо `slowT/slowScale/hitstopT/timeScale` не трогать.
  Регулятор: замедление не продлевается наложением; кулдаун после замедления (`SLOWMO_MODES`, настройка
  `slowmoMode`: normal/rare/off, по умолчанию rare); бюджет — доля замедленного времени за 8 с; идеальный уклон
  обходит кулдаун; стоп-кадры в серии ударов затухают (×0.6 каждый, окно 0.9 с), один стоп-кадр на атаку.
  **Плавность**: `timeScale` — пружина (критическое демпфирование) к цели: вход w=17 (≈0.25 с), выход w=7 (≈0.65 с,
  ease-out); значение и скорость непрерывны при наложении/прерывании. Единственный разрыв — стоп-кадр, после него
  разгон с 15% за 0.12 с. Конец замедления подтягивается к ближайшей доле (+0.3/−0.06 с, добивание не укорачивается).
  Бюджет учитывает и мягкий выход (+0.45 с). На дропе/кульминации замедление глубже (×0.9), кулдаун зрелищных ×0.85.
  Места вызова: идеальный уклон (на HP ≤ 30% — 0.7 с и 0.25), зрелищный удар (вихрь на сильной доле, усиленное
  убийство, точное убийство на сильной доле drop/climax), последний враг волны (priority takedown), добивание, финал.
  `timefx-test.js` печатает `maxScaleStep60` (цель ≤ 0.08 изменения масштаба за 1/60 с вне стоп-кадра).
  Если `slowmo` для добивания отклонён — сценарий идёт ускоренно (`td.speed = 1.65`).
  Без регулятора в толпе было 34% времени в замедлении, 19 входов/мин, 162 мс стоп-кадров в секунду — игра
  «казалась тормозящей». Цели `tools/timefx-test.js`: ≤ 15%, ≤ ~8/мин, интервал ≥ 2.5 с, стоп-кадры ≤ ~70 мс/с.
- Замедления заметно влияют на баланс (замедляют и врагов). Меняя частоту замедлений — перепроверять `balance-test.js`.
- Музыка никогда не замедляется; всё ритмическое считается от аудиочасов (`getOutputTimestamp`),
  нажатия переводятся в музыкальное время по `event.timeStamp`.

## Android APK
- **Собирать APK только по явной просьбе пользователя** (не после каждого изменения).
- `bash tools/build-apk.sh` → `dist/SyncStrike.apk` (dist/ и android/build/ в .gitignore). Без Gradle:
  aapt2 → javac (-source/-target 1.8, bootclasspath android.jar) → d8 → zipalign → apksigner.
  **build-tools 35.0.0 обязательно**: d8 8.2.2 из build-tools 34 падает с NPE на вложенных классах.
- SDK ставится в `/root/android-sdk` (cmdline-tools → `sdkmanager --sdk_root=... "platforms;android-34" "build-tools;35.0.0"`);
  в новой сессии контейнера его нужно ставить заново.
- `android/src/.../MainActivity.java`: WebView с `file:///android_asset/index.html`, immersive fullscreen,
  `sensorLandscape`, выбор файла (`GameChromeClient` → ACTION_GET_CONTENT audio/*), «Назад» через `window.__game`
  (бой → пауза, экран → назад, меню → выход), `web.onPause()` → visibilitychange → пауза боя.
- Подпись — `android/debug.keystore` (пароль android, alias syncstrike) закоммичен намеренно: одинаковый ключ
  в каждой сборке, чтобы обновления ставились поверх без удаления (и без потери настроек). Для Google Play нужен свой ключ.
- versionCode = число коммитов. Иконка — `tools/make-icon.js` (рендер скина «Тень» из игры) → `android/res/mipmap-*`.
  Перегенерация: `node tools/make-icon.js <512.png>` и `convert` (Lanczos) в 48/72/96/144/192 px → `mipmap-mdpi..xxxhdpi/ic_launcher.png`; после смены облика «Тени» обязательно.
- Эмулятор в контейнере не запустить (нет /dev/kvm) — APK на устройстве не проверен, говорить об этом.

## Звуки
- Записанные звуки Kenney.nl (CC0): манифест `tools/sounds.json` (событие → файлы паков, макс. длина).
  Пересборка: скачать паки (ссылки в `_packs` манифеста) в отдельную папку scratchpad, распаковать каждый в
  `<папка>/<pack>/x/`, затем `python3 -I tools/build-sounds.py <папка>` → `src/js/02b_sounddata.js` → `node tools/build.js`.
  Формат WAV моно 22050 Гц: декодируется везде, нет задержки старта, как у MP3 (важно для звуков в такт).
- `SFX.sample(name, {vol, rate, vary, bus})` играет случайный вариант без повтора подряд; каждый метод SFX
  сначала пробует сэмпл, иначе синтез. Настройка `sfxStyle`: samples | synth. Perfect, метроном, прыжок — только синтез.
- Источники и лицензии — `CREDITS.md` (обновлять при смене звуков).

## Работа с агентами
- По просьбе пользователя параллельные задачи отдаются агентам (модель sonnet) с `isolation: "worktree"`; каждому —
  своя зона файлов, чтобы не было конфликтов. Копии лежат в `.claude/worktrees/` (в .gitignore, не коммитить;
  stop-хук ругается на них, если cwd оказался внутри — это не изменения основной ветки).
- Слияние: `git merge <ветка агента>`; конфликт в `index.html` не разрешать вручную — взять любую сторону и
  пересобрать `node tools/build.js`. После слияния — полный набор тестов и проверка скриншотов агентов глазами.
  Затем `git worktree remove` (у заблокированной копии — `-f -f`) и удаление веток агентов.
- Частые конфликты слияния — CLAUDE.md, README.md, общие тесты (`perf-test.js`, `gpu-test.js`): объединять обе стороны.
  Для параллельных агентов, добавляющих однотипное (арены, скины), заранее выделять отдельные файлы-модули (как 09b/09c + 09z).
- Scratchpad у агентов общий — просить называть свои скрипты с префиксом, иначе перезаписывают друг другу.
- Пока агент работает, его незакоммиченную/недоделанную работу не пушить в основную ветку (она = актуальная версия у пользователя).
