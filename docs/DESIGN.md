# Sync Strike — проектный документ (этап 2)

Выбранная концепция: **B · Shadow Strike** с неоновой графикой. Персонажи маленькие, в масштабе Hollow Knight.
Дополнительные требования: набор фонов, которые подбираются под загруженный трек; эффекты, реагирующие
на синхронизацию; скины одежды; настройка размера и прозрачности кнопок.

---

## 1. Визуальная концепция «Неоновая тень»

**Основа:** чёрные силуэты на фоне многослойных декораций. Неон использован как контровой свет:
им светятся кромка плаща, глаза маски, лезвие, выстрелы и детали окружения. В тёмных частях трека
неон тусклый. На сильных долях и в кульминациях он разгорается.

**Масштаб:** персонаж занимает около 11 % высоты экрана (≈ 40 единиц мира при видимой высоте 360).
Маленький размер даёт место для выразительных поз, широких дуг удара и движения камеры, как в
метроидваниях. Рост и вес персонажа передаются через squash & stretch, наклон корпуса и инерцию плаща.

**Персонажи:** большая маска-голова, короткое тело, плащ с вторичной анимацией на пружинах, тонкие
конечности. Типы врагов различаются в первую очередь силуэтом, цвет неона их дополнительно маркирует:

| Тип | Силуэт | Неон | Характер |
|---|---|---|---|
| Клинок (ближний бой) | сгорбленный, парные ножи | маджента | сближается, замах, выпад |
| Стрелок | высокий, длинный плащ, ружьё | янтарь | держит дистанцию, лазер-прицел |
| Вихрь (быстрый) | маленький, низкая стойка, шарф | лайм | рывки, смена сторон |
| Молот (тяжёлый) | массивный, ×1.6, молот | фиолет | долгий замах, ударная волна |

**Скины игрока** (выбор в меню «Облик», все открыты):
Тень (циан, рожки), Ронин (алый, шляпа), Призрак (фиолет, капюшон), Вольт (жёлтый, антенна),
Сакура (розовый, бант), Мотылёк (мятный, усики). Скин задаёт форму головы, цвет маски, глаз, неона и
шарфа. **Враги** при появлении получают случайный вариант снаряжения: капюшон, шлем или повязку,
а также оттенок одежды.

**Палитра интерфейса:** графит `#0b0c10`, кость `#e8e2d6`, циан `#3ef0ff`, маджента `#ff2e88`,
алый `#ff2d4a` (опасность). Шрифты: Oswald (заголовки), IBM Plex Sans (текст), JetBrains Mono (цифры).
Шрифты загружаются с Google Fonts, без сети используются системные запасные.

### Арены, которые подбираются под трек

| Арена | Под что подходит | Реакция на музыку |
|---|---|---|
| Неоновый город | электроника, средний и высокий темп | вывески мигают на долях, дождь густеет от верхов |
| Цифровая бездна | агрессивная электроника, плотный бас | сетка пульсирует, стробы на сильных долях |
| Литейный цех | рок, плотная середина спектра | печи разгораются от баса, искры на сильных долях |
| Лунная крыша | спокойная музыка | луна «дышит» басом, туман густеет с энергией |
| Храм в тумане | эмбиент, редкие события | фонари качаются в такт, лепестки по верхам |
| Собор лучей | кинематографичная музыка | световые лучи растут к кульминации |

Подбор работает **по характеристикам сигнала, а не по жанру**: BPM, доля баса и верхов, плотность
событий, динамический диапазон, средняя энергия, перкуссионность. Каждая арена задаёт целевой
профиль. Итоговый процент совпадения показан в списке фонов, лучший вариант помечен «Авто».
Выбор вручную сохраняется для конкретного трека.

**Общие эффекты синхронизации** (во всех аренах): кольцо на полу на сильной доле, пульсация
виньетки, яркость неона от `beatPulse`, лёгкий «толчок» камеры на басу, вспышки частиц на
высокочастотных событиях, мягкая волна цвета при смене секции трека, плавное смешивание состояний
«спокойно» и «интенсивно» с характерным временем около 1.5 с.

## 2. Игровой цикл

```
requestAnimationFrame(now)
 ├─ dtReal = min(now - last, 50 ms)
 ├─ AudioManager.songTime()            — позиция трека с учётом задержек
 ├─ RhythmAnalyzer.updateLive()        — спектр в реальном времени (AnalyserNode)
 ├─ RhythmClock.update(songTime, live) — фаза, доли, события долей кадра
 ├─ InputManager.poll()                — кнопки, джойстик, буфер нажатий с метками времени
 ├─ если бой и не пауза:
 │    hitstop > 0 ? (пропуск симуляции) :
 │    accumulator += dtReal × timeScale
 │    while accumulator ≥ 1/120: simulate(1/120)   (физика, ИИ, бой, волны)
 ├─ ParticleSystem.update(dtReal × timeScale)
 └─ render: Arena → сущности → эффекты → HUD → сенсорные кнопки
```

Логика (фиксированный шаг 1/120 с) отделена от отрисовки. Замедление времени и стоп-кадр влияют
только на симуляцию. Музыка не замедляется, поэтому синхронизация не теряется.

## 3. Алгоритм музыкальной синхронизации

### 3.1. Офлайн-анализ трека (после загрузки)
1. Декодирование `decodeAudioData`, сведение в моно, понижение частоты дискретизации до ~22 кГц.
2. STFT: кадр 1024, шаг 256 (~86 кадров/с), окно Ханна, собственная FFT.
3. Для трёх полос (низ 30–160 Гц, середина 160–2500 Гц, верх 2500–11000 Гц) считаются энергия
   и **спектральный поток** (рост логарифмической амплитуды). Это детектор начала нот,
   который реагирует на изменение спектра, а не на абсолютную громкость.
4. Огибающая событий: взвешенная сумма потоков полос, из неё вычитается локальное среднее.
5. **Темп:** автокорреляция огибающей на лагах 55–210 BPM с логнормальным априорным весом вокруг
   120 BPM и учётом гармоник (2×, ½×). Поверх этого строится локальный темп в окнах по 10 с,
   отсюда оценка стабильности.
6. **Доли:** динамическое программирование (Ellis, 2007). Каждая доля выбирается так, чтобы
   совпасть с сильным событием и сохранить равномерный интервал. Дальше уточнение по локальному
   пику с параболической интерполяцией. Тихие участки достраиваются сеткой с пометкой «низкая
   уверенность».
7. **Сильные доли:** голосование фаз по модулю 4 по энергии баса в блоках по 32 доли, с гистерезисом.
8. **Энергия и секции:** сглаженная огибающая, точки смены энергии привязываются к ближайшей сильной
   доле, уровни «спокойно / средне / интенсивно».
9. **Уверенность:** выраженность пика автокорреляции, доля долей с реальными событиями,
   стабильность темпа. По ней выбирается режим:
   * **точный** — уверенность ≥ 0.6 и стабильный темп;
   * **адаптивный** — средняя уверенность или плавающий темп, окна шире, сильнее подстройка фазы;
   * **резервный** — слабый ритм, ровная сетка по оценке BPM, фаза подстраивается по живым
     событиям, окна ×1.4.

Анализ идёт порциями с `setTimeout(0)`, поэтому интерфейс не зависает и показывает прогресс.
Файл никуда не отправляется, вся обработка локальная.

### 3.2. Время и задержки
```
songTime = позиция_источника − outputLatency − калибровка_пользователя
позиция_источника = offset + (ctx.currentTime − startCtxTime)
```
* Воспроизведение идёт через `AudioBufferSourceNode`. Пауза и перемотка пересоздают источник
  с нужным смещением, позиция всегда вычисляется от аудиочасов, поэтому накопленного дрейфа нет.
* Нажатие переводится в музыкальное время по `event.timeStamp`, а не по моменту обработки кадра.
* **Калибровка:** экран с метрономом (щелчки по аудиочасам на предсказанных долях) и тест
  «нажимай в такт» из 12 касаний. Медиана отклонений записывается в задержку, ручной ползунок
  ±250 мс остаётся доступен.

### 3.3. RhythmClock (единый музыкальный контроллер)
Предоставляет всем системам: `phase`, `period`, `bpm`, `prevBeat/nextBeat`, `timeToNext`,
`strong`, `beatPulse`, `strongPulse`, `intensity`, `bands{low,mid,high}`, `confidence`, `mode`,
`section`, события кадра `beat`/`strongBeat`/`onset`/`section`, а также `judge(t)` и
`nextBeatAfter(t)`. Игровые объекты сами аудио не анализируют.

Живая коррекция фазы: если живое событие баса попадает в ±25 % периода от предсказанной доли,
поправка смещается к нему с коэффициентом 0.02 / 0.05 / 0.1 (точный / адаптивный / резервный)
и ограничена ±30 / 50 / 80 мс.

### 3.4. Ритмические окна (масштабируются темпом)
| Оценка | Окно |
|---|---|
| Perfect | ±clamp(0.11·P, 45, 75 мс) × масштаб |
| Good | ±clamp(0.22·P, 90, 150 мс) × масштаб |
| Early / Late | до ±0.38·P |
| Miss | дальше (атака всё равно выполняется, но слабее) |

При BPM < 90 оценка ведётся и по половинным долям. **Буфер ввода:** если нажатие раньше доли
не больше чем на min(160 мс, 0.3·P), подготовка удара растягивается, и удар приходится точно на
долю. Оценка при этом остаётся честной, по моменту нажатия. Нажатие во время восстановления
запоминается на 220 мс.

## 4. Модели состояний

### Игрок
```
idle ⇄ run ⇄ walk          (по джойстику; |x|<0.65 — шаг)
idle/run → jump → fall → land → idle     (койот-время 80 мс, буфер прыжка 100 мс,
                                           переменная высота, двойной прыжок)
любое подвижное → dodge (0.22 с, i-frames 0.18 с, перезарядка 0.45 с)
любое подвижное → attack:{slash1|slash2|slash3|dash|shot|charged|dive|airSlash}
attack → (cancelWindow) → следующая атака / dodge / jump
любое → hurt (0.3 с, отбрасывание, i-frames 0.6 с) → idle/fall
hp=0 → dead;  победа → victory
```
Каждая атака описывается фазами: `startup → active → recovery`, плюс `cancelFrom` (с какого
момента можно прервать). Неуязвимость дают только перемещение рывковой атаки и уклонение.

### Выбор атаки (одна кнопка)
1. Цель выбирается по баллу: расстояние, направление взгляда, высота, «липкость» к прошлой цели,
   низкое HP.
2. Учитывается дистанция до кромки цели:
   * ≤ 36: кинжальная цепочка slash1 → slash2 → slash3; slash3 на сильную долю даёт вихрь «Нокс»;
   * ≤ 170 (+40 при Good и выше): рывок с ударом. При Miss на дистанции > 110 вместо рывка выстрел;
   * дальше: выстрел «Импульс-7». Третий выстрел серии с Perfect становится заряженным и пробивает;
   * в воздухе: цель ниже — удар вниз с отскоком (pogo), иначе воздушный удар или выстрел.
3. Связки: после slash3 враг отлетает, выстрел в течение 0.6 с даёт «Эхо»; рывок после выстрела
   даёт «Дуэт».

### Враги
```
spawn(0.6 с, неуязвим) → think ⇄ approach / keepDistance / strafe / retreat
think → (жетон атаки получен) → windup (удар назначается на долю) → attack → recover → think
любой → hurt (если сломана стойкость) → think;  hp=0 → dead (распад на неоновые осколки)
```
* **AttackDirector:** одновременно атакуют не больше `1 + волна/2` врагов (максимум 3), стрелков
  не больше 2. Если следующая атака идёт с другой стороны от игрока, нужен зазор 0.7 с вместо 0.35 с.
  Атаки со всех сторон одновременно невозможны.
* **Знания врагов ограничены:** дальность обзора, задержка реакции 0.15–0.3 с, прицел фиксируется
  за 0.15 с до выстрела, проверка дистанции перед атакой.
* **Музыка:** удар врага назначается на ближайшую долю после минимального замаха. В интенсивных
  секциях перезарядка ×0.7, в спокойных ×1.3. На долях враги покачиваются, на сильных принимают
  угрожающую позу.

## 5. Мобильное управление

* Слева джойстик. По умолчанию плавающий: появляется там, где коснулся палец. Есть режим
  фиксированного.
* Справа большая кнопка «Атака», кнопки «Прыжок» и «Уклон». Пауза вверху справа.
* Pointer Events с отслеживанием `pointerId` дают сколько угодно одновременных касаний.
  `touch-action: none`, без выделения, без контекстного меню, без зума двойным касанием.
* Зона касания на 25 % больше видимой кнопки. Нажатая кнопка подсвечивается и уменьшается.
* **Настройки управления:**
  * общий размер кнопок 60–150 %;
  * **отдельный ползунок прозрачности** 10–100 %;
  * **редактор раскладки**: перетаскивание кнопок, выбор кнопки и её собственный размер,
    сброс к стандартной;
  * режим джойстика.
* Раскладка хранится в долях экрана и учитывает safe-area (вырезы, полосы жестов), поэтому
  подходит к любому соотношению сторон. Настройки сохраняются в `localStorage`.
* ПК: A/D или ←/→ движение, W/↑/Пробел прыжок, J или ЛКМ атака, K/Shift/ПКМ уклон, Esc/P пауза.
* В бою при вертикальной ориентации показывается оверлей «поверните устройство», игра встаёт
  на паузу. Состояние при этом не сбрасывается.

## 6. Классы и ответственность

| Модуль | Ответственность |
|---|---|
| `Game` | главный цикл, состояние экрана и боя, связывание систем |
| `Settings` / `Store` | значения по умолчанию, сохранение в `localStorage` |
| `InputManager` | клавиатура, мышь, сенсор, очередь нажатий с музыкальным временем |
| `TouchControls` | раскладка, отрисовка, редактор кнопок |
| `AudioManager` | AudioContext, шины громкости, трек, пауза и перемотка, songTime |
| `SFX` | синтезированные эффекты, ограничение голосов, вариации высоты |
| `DemoTrack` | встроенный синтезированный трек для обучения и проверки |
| `RhythmAnalyzer` | офлайн-анализ (FFT, поток, темп, доли, секции, признаки) и живой спектр |
| `RhythmClock` | предсказание долей, окна, оценки, события, коррекция фазы |
| `AnimationSystem` | смешивание поз, пружины плаща и шарфа, процедурные позы |
| `CharacterRenderer` / `Skins` | отрисовка силуэтов и неона, скины игрока и врагов |
| `Player` | физика, состояния, действия игрока |
| `Enemy` (+ Blade, Gunner, Swift, Brute) | базовая логика и ИИ типов |
| `CombatSystem` | выбор цели и атаки, хитбоксы, урон, комбо, очки, замедление |
| `AttackDirector` / `WaveDirector` | справедливое распределение атак, волны и спавн |
| `ParticleSystem` | пул частиц, остаточные изображения, тексты оценок |
| `ArenaRenderer` (+ темы) | слои параллакса, реакция на музыку, переходы, подбор арены |
| `Camera` | следование, толчки, тряска |
| `HUD` / `UIManager` | интерфейс боя, экраны меню, настройки |

**Режимы игры:** «Волны» (6 волн, трек зациклен), «До конца трека» (сложность следует за энергией
трека, победа, если продержаться до конца), «Практика» (обучение с подсказками, без поражения).

**Расширяемость:** новое оружие добавляется записью в `ATTACKS`, враг — подклассом `Enemy` и
строкой в `ENEMY_TYPES`, арена — объектом в `THEMES` с профилем подбора, скин — записью в `SKINS`.
